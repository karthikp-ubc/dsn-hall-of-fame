# CLAUDE.md — DSN Hall of Fame website

This file documents the front-end (`dsn-hof.html`, `logic.js`, `app.js`) and its
data pipeline, for whoever (human or Claude) works on this next. It does not cover
`isca.py` / `isca-parallel.py` / `ISCA-README.rst`, which are a separate, unrelated
tool bundled in this repo.

## What this is

A static site that ranks DSN/FTCS conference authors by publication count, sourced
from DBLP. There is no backend and no build step: `dsn-hof.html` is opened directly
(or served by any static file server) and reads `ranking.json` via `fetch`.

## File map

```
dsn-hof.html      Markup, CSS, and script tags. No inline logic beyond the
                   pre-existing getLastMod() helper (last-modified-date display).
logic.js          Pure, DOM-free functions: filtering by year range, ranking,
                   sorting, color assignment, entity decoding. Loaded by both the
                   browser (window.DSNLogic) and Node tests (module.exports).
app.js            DOM rendering, Chart.js wiring, event handlers. Consumes
                   DSNLogic from logic.js — must be loaded AFTER logic.js.
ranking.json      Generated data the website reads. One entry per author:
                   { anchor, num, rank, author, total, recent, affiliation, years }
                   `years` is a sparse dict of {"YYYY": count}, all-time.
                   `rank`/`total` are the all-time values from the original crawl.
authorlist.json   Generated by dsn-ranking.py: raw per-author dblp publication
                   keys (pid -> {name, pubs, ...}). Checked in so ranking.json can
                   be re-derived (see backfill_years.py) without re-crawling DBLP.
dsn-ranking.py    The crawler: queries DBLP for DSN (2000-present) and FTCS
                   (1988-1999), builds authorlist.json, then ranking.json
                   (including affiliation lookups, which do hit DBLP).
backfill_years.py One-off script: re-derives ranking.json's `years` field from
                   the already-crawled authorlist.json, with no network calls.
                   Use this instead of re-running dsn-ranking.py when only the
                   per-year breakdown needs updating.
dblp/             Vendored DBLP API client used by dsn-ranking.py.
tests/            pytest (crawler/data pipeline) + tests/js (Node, logic.js).
```

## Data flow

```
DBLP  --dsn-ranking.py-->  authorlist.json  --(get_year_breakdown)-->  years field
                                  |                                        |
                                  +---------------> ranking.json <---------+
                                                        |
                                                  dsn-hof.html (fetch)
```

`dsn-ranking.py` and `backfill_years.py` both compute the per-year breakdown via
the same `get_pub_year` / `get_year_breakdown` functions (defined once in
`dsn-ranking.py`, imported by `backfill_years.py`) — don't duplicate that logic.

## Front-end architecture decisions

- **Zero build step, on purpose.** No npm, no bundler, no framework. Plain
  `<script>` tags, `fetch`, template literals, ES6 classes-free vanilla JS. This
  matches the rest of the repo (a small Python crawler + static output) and keeps
  deployment to "copy the files somewhere static file servers can reach."
  Chart.js is the one exception, loaded from cdnjs — reintroducing a JS charting
  library from scratch wasn't worth it. If this ever grows enough to need real
  componentization, that's a deliberate architecture change, not an incremental one.
- **`logic.js` / `app.js` split exists for testability.** Anything that doesn't
  touch the DOM (filtering, ranking, sorting, color assignment, entity decoding)
  lives in `logic.js` and is exported both as `window.DSNLogic` (browser) and via
  `module.exports` (Node), so it can be unit-tested with Node's built-in test
  runner without a DOM shim like jsdom. `app.js` should stay a thin rendering/event
  layer over `DSNLogic` — if you add non-trivial branching logic to app.js, ask
  whether it belongs in logic.js instead so it can be tested.
- **Ranking is recomputed client-side per year range**, not precomputed
  server-side for every possible range. `logic.js`'s `getFilteredRows(allData,
  fromYear, toYear)` sums each author's `years` entries within range, drops
  authors with 0 papers in range, and assigns standard competition ranking
  (1, 2, 2, 4 — ties share a rank, the next rank skips accordingly) scoped to that
  range. The original all-time `rank`/`total` from `ranking.json` are preserved
  per-row as `allTimeRank`/`allTimeTotal` so the author modal can show both.
- **Compare-mode color assignment is by entity, not by position.** `logic.js`'s
  `createColorAssigner` hands out palette colors in first-seen order and then
  never changes them — so if you deselect and reselect authors, or the sort order
  changes, a given author keeps their color instead of the chart repainting.
  This follows the dataviz skill's rule: "color follows the entity, never its
  rank." The categorical palette (8 colors, `CATEGORICAL` in `app.js`) is the
  dataviz skill's validated default order — don't reorder it casually, since the
  order is itself the colorblind-safety mechanism (see the skill's `palette.md`
  for the adjacent-pair validation this order passes). Compare mode caps plotted
  series at 8 (`MAX_COMPARE_SERIES`) for the same reason; beyond that, `app.js`
  shows a "showing N of M" note rather than degrading the palette.
- **HTML entities in the data must be decoded before display, without
  `innerHTML`.** DBLP-sourced affiliation strings sometimes contain literal
  `&amp;` etc. `logic.js`'s `decodeEntities` handles the known entity set via
  regex replacement — no DOM parsing, so it's Node-testable and doesn't reopen
  the injection risk `innerHTML` would carry for author-supplied-ish data. Always
  route author/affiliation text through `decodeEntities` before `textContent`
  assignment (never `innerHTML`) when rendering data-sourced strings.
- **`<meta charset="utf-8">` is required in `dsn-hof.html`.** Without it, plain
  HTTP servers that don't send a charset header (e.g. Python's `http.server`)
  leave the browser guessing, and non-ASCII characters (en dashes, names with
  diacritics) render as mojibake. Don't remove this tag.

## Coding style

- Tabs for indentation in `.js`/`.html` (matches the pre-existing `load.js` this
  code replaced). 4-space indent in Python (matches the existing crawler code).
- `app.js` and `logic.js` are each wrapped in an IIFE / UMD-style closure — no
  global leakage besides the single `window.DSNLogic` export.
- No comments explaining *what* code does; comments only where the *why* isn't
  obvious from the code itself (e.g. the caching gotcha below, the palette-order
  rationale above).
- Prefer extending `logic.js` with a new pure function + test over adding
  branchy logic directly in a DOM event handler.

## Known gotcha: browser caching during local testing

Chrome (including via the claude-in-chrome automation tooling) has been observed
serving a stale cached copy of `app.js`/`dsn-hof.html` across repeated `navigate`
calls to the same local dev server, even though the server returns 200 (not 304)
with fresh content on every request. If a change doesn't appear to take effect
while testing locally, hard-refresh (`Ctrl+Shift+R` / `Cmd+Shift+R`) or open a
private/incognito window before concluding there's a real bug.

## Known data-quality quirks (pre-existing, not introduced by the website work)

- `get_pub_year`'s two-digit-year rule (`>50` → 1900s, `<=50` → 2000s) means a
  hypothetical key ending in exactly `...50` maps to 2050, not 1950. This hasn't
  mattered in practice (DSN/FTCS data only spans 1988–present) but is worth
  knowing if DBLP's key format ever surprises you.
- Author name matching (both within the crawler and in `backfill_years.py`'s
  `ranking.json` ↔ `authorlist.json` join) is by exact DBLP display name, not by
  DBLP pid. Homonyms are not merged or split — see `README.rst`'s "Missing
  Features" section for the existing discussion of this limitation.

## Testing

- **Python** (`dsn-ranking.py`, `backfill_years.py`, `dblp/`): `pytest` from the
  repo root. `tests/conftest.py` provides a `dsn_ranking` fixture that loads
  `dsn-ranking.py` fresh per test (it can't be `import`ed normally — hyphenated
  filename) and a `block_real_network` autouse fixture that fails any test which
  forgets to mock `dblp.requests.get`.
- **JavaScript** (`logic.js`): `node --test tests/js/logic.test.js` from the repo
  root. No npm install needed — uses Node's built-in test runner and assert
  module only. `app.js` itself (DOM rendering/event wiring) is not unit-tested;
  it's covered by manual/browser verification when making UI changes.

Run both before considering a front-end change done: `pytest -q && node --test
tests/js/logic.test.js`.
